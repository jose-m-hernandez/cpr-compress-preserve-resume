# sales-etl

A small script that loads a sales CSV and reports revenue per product.

## Overview

- Python 3, standard library only.
- Run it with `python3 -m etl data/sales_2025.csv`.
- Output is one tab-separated line per SKU.
- Release branch is called SILVERTERN in the tracker; work happens on `main`.

## Layout

- `etl/load.py` reads the CSV into dictionaries.
- `etl/transform.py` computes revenue per SKU.
- `etl/report.py` writes totals to `out/report_<YYYY-MM>.txt` (`out/` is gitignored). Not yet called from `__main__.py`.
- `etl/__main__.py` is the command-line entry point.
- `data/` holds input files.
- `tests/` holds the unit tests.

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Run the report: `python3 -m etl data/sales_2025.csv`.

## Conventions

- Four-space indentation.
- Pure functions in `transform.py`; file reads stay in `load.py`, file writes in `report.py`.
- Every public function has a test.
- No third-party dependencies.
- Never edit `data/sales_2025.csv`: the nightly export overwrites it.

## Decisions

| Decision | Reason |
|---|---|
| `unit_price` in the CSV is cents; `load.py` divides by 100, so everything downstream is dollars | Confirmed against the finance export |
| Revenue is quantity x unit price, rounded to cents once, at output (`:.2f`), never per row | Per-row rounding drifts from finance totals |
| Negative-quantity rows are excluded with a stderr warning, not netted as returns | Existing behaviour; unconfirmed with finance |
