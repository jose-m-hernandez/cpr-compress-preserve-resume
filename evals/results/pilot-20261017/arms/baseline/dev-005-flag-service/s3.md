# flag-service

A small HTTP service that answers whether a feature flag is on.

## Overview

- Python 3, standard library only.
- Start the server with `python3 -m flags.app`.
- `GET /flags/<name>` answers with JSON such as `{"enabled": true}`.

## Layout

- `flags/app.py` is the HTTP layer.
- `flags/store.py` defines and evaluates flags.
- `flags/loader.py` reads the flag file (`load_flags`); `store.py` still writes it in `define`.
- `flags/validate.py` checks flag names (lowercase kebab-case, `^[a-z][a-z0-9-]*$`).
- `flags/cache.py` caches evaluations for a short time (30 seconds, `TTL_SECONDS`).
- `config/flags.json` holds the flag definitions.
- `tests/` holds the unit tests.

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Query a flag: `curl http://127.0.0.1:8090/flags/dark-mode` once the server is running.

## Conventions

- Four-space indentation.
- Keep the HTTP layer thin and put logic in the store.
- Every public function has a test.
- No third-party dependencies.
- Tests must never touch `config/flags.json`: the running service reads it live. Use a temp file, and don't import `flags.app` in tests (its module-level `STORE` points at the live file).

## Decisions

| Decision | Reason |
| --- | --- |
| Cache TTL is 30 seconds, down from 60 | Flags change often enough that 60 was stale |
| `evaluate()` returns `False` for an unknown flag and never raises | Requested behavior; tested in `tests/test_store.py` |

## Known issues

- `flags/app.py` still catches `KeyError` and returns 404, which can no longer happen. Unknown flags now get 200 `{"enabled": false}`. Remove the dead branch or restore 404 deliberately.
- `flags/app.py` has no tests.
- `evaluate()` still raises if the flag file is missing or holds invalid JSON.
- `test_cache_expires_after_the_ttl` sets its own TTL, so it does not check `TTL_SECONDS`.
