# flag-service

A small HTTP service that answers whether a feature flag is on.

## Overview

- Python 3, standard library only.
- Start the server with `python3 -m flags.app`.
- `GET /flags/<name>` answers with JSON such as `{"enabled": true}`.

## Layout

- `flags/app.py` is the HTTP layer.
- `flags/store.py` defines and evaluates flags.
- `flags/loader.py` reads the flag file (`load_flags`); `store.py` still writes it in `define`.
- `flags/validate.py` checks flag names (lowercase kebab-case, `^[a-z][a-z0-9-]*$`).
- `flags/cache.py` caches evaluations (`TTL_SECONDS = 30`).
- `config/flags.json` holds the flag definitions. The running service reads it live.
- `tests/` holds the unit tests.

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Query a flag: `curl http://127.0.0.1:8090/flags/dark-mode` once the server is running.

## Conventions

- Four-space indentation.
- Keep the HTTP layer thin and put logic in the store.
- Every public function has a test.
- No third-party dependencies.
- Tests must use a temporary flags file and never write to `config/flags.json`. Do not import `flags.app` in tests, since its module-level `STORE` points at the live file.

## Decisions

| Decision | Reason |
|---|---|
| Cache TTL is 30 seconds | Flags change often enough that 60 was stale. |
| `evaluate()` returns `False` for an unknown flag and never raises | Requested behavior. Unknown results are not cached. |
