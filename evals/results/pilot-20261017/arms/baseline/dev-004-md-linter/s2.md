# mdcheck

A small command-line linter for Markdown files.

## Overview

- Python 3, standard library only.
- Run it with `python3 -m mdcheck FILE [FILE ...]`.
- Findings print as `path:line: rule: message`.
- Options: `--rules a,b` picks rules, `--config PATH` reads a JSON file like `{"rules": ["no-tabs"]}` (conventionally `.mdcheck.json`), `--format text|json`.
- Release branch is called AMBERKITE in the user's notes. Work is on `main`; nothing from the rules/config/format work is committed yet.

## Layout

- `mdcheck/rules.py` holds the lint rules, the `RULES` registry and `WARNING_RULES`.
- `mdcheck/runner.py` applies the rules to files (`check_files`) and loads the config (`load_config`).
- `mdcheck/formats.py` formats findings for text and json output.
- `mdcheck/cli.py` parses arguments and prints findings.
- `mdcheck/errors.py` holds exception types and exit codes.
- `samples/` holds example Markdown files.
- `docs/rules.md` documents each rule, the config file and the output formats.
- `tests/` holds the unit tests (`test_rules`, `test_cli`, `test_config`, `test_formats`).

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Lint a sample: `python3 -m mdcheck samples/good.md`.

## Conventions

- Four-space indentation and type hints on public functions.
- One function per rule, with a test for each, registered in `RULES` and documented in `docs/rules.md`.
- No third-party dependencies.
- Exit code 0 means clean (or warnings only), 1 means error findings, 4 means a config error (bad config file or unknown rule).

## Decisions

| Decision | Why |
|----------|-----|
| `heading-increment` is a warning; warnings alone exit 0 | The user asked for a warning, not an error. Warning rules are listed in `WARNING_RULES`. |
| `--rules` overrides `--config` | Command line beats file. |
| JSON output has only `path`, `line`, `rule`, `severity` | Exactly the keys the user specified; no `message`. |
| `line-length` limit is 88 | Matches the user's other tools. |

## Warnings

- Do not point a self-check at `docs/rules.md`: it quotes bad examples on purpose and will always report findings.
- `trailing-space` also flags Markdown's two-space hard line break.
- `no-bare-urls` only handles `http`/`https` and its link detection is regex-based.
- `RULES` is in the order rules were added, not alphabetical; reordering changes output order.
