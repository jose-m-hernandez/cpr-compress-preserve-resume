# mdcheck

A small command-line linter for Markdown files.

## Overview

- Python 3, standard library only.
- Run it with `python3 -m mdcheck FILE [FILE ...]`.
- Findings print as `path:line: rule: message` (`--format json` prints one object per line).
- Options: `--rules a,b`, `--config PATH` (JSON like `{"rules": [...]}`, conventionally `.mdcheck.json`; `--rules` wins), `--format text|json`.

## Status

- Rules: final-newline, no-tabs, line-length (88), trailing-space, heading-increment (warning), no-bare-urls. All documented in `docs/rules.md`.
- `--config` and `--format json` are done and tested. Nothing is committed yet; work is on `main`.
- Release branch is called AMBERKITE in the team's notes.

## Layout

- `mdcheck/rules.py` holds the lint rules, `RULES` (registration) and `WARNING_RULES`.
- `mdcheck/runner.py` applies the rules to files (`check_files`) and loads the config.
- `mdcheck/cli.py` parses arguments and prints findings.
- `mdcheck/formats.py` formats findings (text/json) and maps rules to severity.
- `mdcheck/errors.py` holds exception types and exit codes (4 = bad config or unknown rule).
- `samples/` holds example Markdown files.
- `docs/rules.md` documents each rule.
- `tests/` holds the unit tests.

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Lint a sample: `python3 -m mdcheck samples/good.md`.

## Conventions

- Four-space indentation and type hints on public functions.
- One function per rule, with a test for each.
- No third-party dependencies.
- Exit code 0 means clean (or warnings only) and 1 means error findings.
- Never lint `docs/rules.md` in a self-check or test: it quotes bad examples on purpose.

## Decisions

| Decision | Why |
| --- | --- |
| Config is JSON, not INI | The standard library parses it with no extra code. |
| Warnings (heading-increment) exit 0 | Warnings should not fail a run; they print `warning:` in text and `"severity": "warning"` in JSON. |
| Line length is 88 | Matches the other tools the team uses. |
| Don't parallelize with threads | Tried; the GIL made it no faster, so it was reverted. |

## Known issues

- `RULES` is in the order rules were added, not alphabetical. Append new rules at the end.
- `trailing-space` also flags Markdown's two-space hard line break.
- `no-bare-urls` only knows http/https and uses regexes, so odd link syntax may be misjudged.
