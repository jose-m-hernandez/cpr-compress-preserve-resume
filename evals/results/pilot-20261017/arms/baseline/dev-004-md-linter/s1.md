# mdcheck

A small command-line linter for Markdown files.

## Overview

- Python 3, standard library only.
- Run it with `python3 -m mdcheck FILE [FILE ...]`.
- Findings print as `path:line: rule: message`.
- Options: `--rules a,b`, `--config PATH` (JSON like `{"rules": [...]}`, usually `.mdcheck.json`), `--format text|json`.
- `--rules` overrides `--config`. Bad config or unknown rule exits 4.

## Status

- Rules: final-newline, no-tabs, line-length (88), trailing-space, heading-increment (warning), no-bare-urls. All documented in `docs/rules.md`.
- `--config` and `--format json` are done and documented.
- Nothing is committed yet; work is uncommitted on `main`. The release branch is called AMBERKITE in the user's notes.

## Layout

- `mdcheck/rules.py` holds the lint rules, the `RULES` registry and `WARNING_RULES`.
- `mdcheck/runner.py` applies the rules to files (`check_files`) and loads the config (`load_config`).
- `mdcheck/cli.py` parses arguments and prints findings.
- `mdcheck/formats.py` formats findings as text or JSON and gives each rule its severity.
- `mdcheck/errors.py` holds exception types and exit codes.
- `samples/` holds example Markdown files.
- `docs/rules.md` documents each rule.
- `tests/` holds the unit tests.

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Lint a sample: `python3 -m mdcheck samples/good.md`.

## Conventions

- Four-space indentation and type hints on public functions.
- One function per rule, with a test for each.
- No third-party dependencies.
- Exit code 0 means clean and 1 means errors. Warnings (rules in `WARNING_RULES`) alone exit 0.
- Register a new rule in `RULES` (not alphabetical, in the order added) and add a section to `docs/rules.md`.
- Never run mdcheck as a self-check on `docs/rules.md`: it quotes bad examples on purpose, so it always reports findings.

## Decisions

- JSON for the config file, not INI: the standard library parses it with no extra code.
- Warnings exit 0 so they never fail a run. Revisit if warnings should exit 1.
- JSON output has no `message` key, only `path`, `line`, `rule`, `severity`.

## Known limits

- `trailing-space` also flags Markdown's two-space hard line break.
- `no-bare-urls` is regex-based and only handles http and https.
- `heading-increment` ignores underlined (setext) headings.
