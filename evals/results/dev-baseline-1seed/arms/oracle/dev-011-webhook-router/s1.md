# router

A small webhook router: it validates incoming events and passes each one to the handler for its type.

## Overview

- Python 3, standard library only.
- Replay a saved event with `python3 -m router replay FILE`.

## Layout

- `router/events.py` parses and checks an incoming event.
- `router/registry.py` maps event types to handlers.
- `router/dispatch.py` turns a request body into a status code and a payload.
- `data/` holds saved example events.
- `tests/` holds the unit tests.

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Try it: `python3 -m router replay data/ping.json`.

## Conventions

- Four-space indentation and docstrings on public functions.
- Keep functions short and give each one a test.
- No third-party dependencies.

## Warnings
- Events older than 300 seconds are rejected as stale (400).
- Blocked: signature verification waits for the sender's signing scheme; requests are unsigned until then.

## Structure
- `router/handlers/` has one module per event family; `orders.py` handles the order events.

## Decisions
- Unknown event types answer 202 `ignored`, not 404: the sender retries any 4xx forever.
- Handlers run inline, no thread pool: the dedupe set is not thread-safe.
- Dedupe remembers the last 5000 event ids (was 1000): the sender's retry window is longer than expected.
- Legacy `kind` is normalised to `type` in one small function; support ends after the March cutover.
- 5xx responses carry `Retry-After: 30`.

## Patterns
- Handler tests build events with `make_event()` in `tests/factory.py` (hand-written dicts miss the id).
