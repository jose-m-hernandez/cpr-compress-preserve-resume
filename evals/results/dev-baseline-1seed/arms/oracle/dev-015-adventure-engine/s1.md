# adventure

A small text-adventure engine: a world of rooms in a JSON file and a state machine that runs player commands.

## Overview

- Python 3, standard library only.
- Validate a world with `python3 -m adventure check FILE`.

## Layout

- `adventure/world.py` loads and validates a world file.
- `adventure/state.py` holds the player's state.
- `adventure/engine.py` runs one command and returns the message.
- `worlds/` holds example world files.
- `tests/` holds the unit tests.

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Try it: `python3 -m adventure check worlds/cave.json`.

## Conventions

- Four-space indentation and docstrings on public functions.
- Keep functions short and give each one a test.
- No third-party dependencies.

## Warnings
- A world file is rejected when an exit names a room that does not exist.
- Blocked: NPC dialogue waits for the writer's script text; use placeholder strings.

## Decisions
- Inventory limit is 6 items (was 4): 4 was too tight with both key and lamp.
- `inspect` is deprecated (removed in version 2); `look at` is the documented form.
- Death returns the player to the last save instead of ending the game.
- No randomness anywhere in the engine: a save must replay identically.

## Structure
- `adventure/saves.py` writes saves as JSON to `saves/NAME.json`.

## Patterns
- Tests use `play(world, commands)` in `tests/helpers.py`, not state objects (they break when state changes shape).
- `quit` confirms only when there are unsaved moves.
