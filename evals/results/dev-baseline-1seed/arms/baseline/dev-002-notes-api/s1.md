# notes-api

A small HTTP service that stores short notes in a JSON file.

## Overview

- Python 3, standard library only.
- Start the server with `python3 -m notes_api.app`.
- Responses are JSON.

## Layout

- `notes_api/app.py` is the HTTP layer.
- `notes_api/store.py` keeps notes in memory and saves them to a file.
- `notes_api/validation.py` holds input checks (`MAX_TITLE`, `validate_title`); the store calls it.
- `config.json` holds runtime settings. The dev server port is 8082 (8081 is taken by the metrics sidecar on dev boxes); keep README.md in step.
- `tests/` holds the unit tests.

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- List notes: `curl http://127.0.0.1:<port>/v1/notes` once the server is running.

## Conventions

- Four-space indentation.
- Keep handlers thin and put logic in the store.
- Every public function has a test.
- No third-party dependencies.
- `/v1` routes are frozen: bug fixes only. All new endpoints go under `/v2`.
- Routes live in the `ROUTES` table in `app.py`. `Handler` only looks them up via `dispatch`; it must not branch on the path.
- Use `NoteStore.find` (returns `None`) for lookups that may miss; `get` raises `KeyError`.

## Status

- Done: `GET` and `DELETE /v2/notes/<id>`. Success returns 200 with a JSON body (DELETE returns `{"id", "deleted": true}`); a missing id returns 404 `{"error": "not found"}`. 15 tests pass.
- The release branch is called COPPERWREN in the tracker (git is on `main`).
