# units

A small library that converts between units of length and mass.

## Overview

- Python 3, standard library only.
- Convert from the command line with `python3 -m units VALUE FROM TO`.

## Layout

- `units/table.py` holds the conversion factors.
- `units/convert.py` does the conversion.
- `units/aliases.py` maps spellings (metre, meter, feet, celsius...) to table units, case-insensitively, via `resolve()`.
- `units/__main__.py` is the command-line entry point.
- `tests/` holds the unit tests.

## Status

- Done and tested: 6-significant-digit rounding, unit aliases, exact pound factor.
- Not started: compound units like `km/h`, the `--list` flag, docs.
- Temperature (C, F, K) is recognised but deliberately rejected: it needs an offset, not a factor.
- Release branch is `QUARTZHERON`.

## Decisions

| Decision | Reason |
|---|---|
| `convert()` rounds with `float(f"{x:.6g}")` | Removes float noise like `0.30000000000000004` for library and CLI alike |
| Stay with floats, not `decimal.Decimal` | Tried it; the examples became too long to read |
| `lb` factor is `0.45359237` | The old `0.4536` lost a gram on 1000 lb |

## Known issues

- Rounding every result makes chained conversions lossy: 1000 lb to g and back gives `999.999`. Open question: round only in the CLI output and keep `convert()` at full precision (fixes round trips, loses noise cleanup for library callers).

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Try it: `python3 -m units 5 km mi`.

## Conventions

- Four-space indentation and docstrings on public functions.
- Keep functions short and give each one a test.
- No third-party dependencies.
