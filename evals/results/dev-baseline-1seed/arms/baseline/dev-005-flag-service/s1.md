# flag-service

A small HTTP service that answers whether a feature flag is on.

## Overview

- Python 3, standard library only.
- Start the server with `python3 -m flags.app`.
- `GET /flags/<name>` answers with JSON such as `{"enabled": true}`.

## Layout

- `flags/app.py` is the HTTP layer.
- `flags/store.py` defines and evaluates flags.
- `flags/loader.py` reads the flag file (`load_flags`); writing still lives in `FlagStore.define`.
- `flags/validate.py` checks flag names (lowercase kebab-case, `^[a-z][a-z0-9-]*$`).
- `flags/cache.py` caches evaluations for 30 seconds (`TTL_SECONDS`).
- `config/flags.json` holds the flag definitions.
- `tests/` holds the unit tests.

## Decisions

| Decision | Reason |
| --- | --- |
| Cache TTL is 30s, not 60s | Flags change often enough that 60s was stale. |
| `evaluate()` returns `False` for an unknown flag and never raises | Requested behavior; unknown results are not cached. |

## Warnings

- `config/flags.json` is read live by the running service. Tests must never write to it; use a temp file (see `tests/test_store.py` `setUp`).
- Do not import `flags.app` in tests: its module-level `STORE` points at the live file.
- `flags/app.py` still catches `KeyError` for a 404, but `evaluate()` no longer raises it, so unknown flags now get 200 `{"enabled": false}`. Remove the dead branch or restore 404 deliberately.
- `evaluate()` still raises if the flag file is missing or invalid JSON.
- `flags/app.py` has no tests.
