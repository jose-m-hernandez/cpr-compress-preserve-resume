# adventure

A small text-adventure engine: a world of rooms in a JSON file and a state machine that runs player commands.

## Overview

- Python 3, standard library only.
- Validate a world with `python3 -m adventure check FILE`.

## Layout

- `adventure/world.py` loads and validates a world file.
- `adventure/state.py` holds the player's state and `INVENTORY_LIMIT` (6).
- `adventure/engine.py` runs one command and returns the message. Commands: `look`, `go`, `take`, `drop`, `save`, `load`, `quit`. `inspect` is a deprecated alias for `look`; remove it in version 2.
- `adventure/saves.py` writes and reads `saves/NAME.json` (room, inventory, per-room items).
- `worlds/` holds example world files.
- `tests/` holds the unit tests. `tests/helpers.py` has `play(world, commands)`.

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Try it: `python3 -m adventure check worlds/cave.json`.

## Conventions

- Four-space indentation and docstrings on public functions.
- Keep functions short and give each one a test.
- No third-party dependencies.
- Nothing in the engine may be random: a save must replay identically. The wandering monster was removed for this reason.
- Tests drive the engine through `play(world, commands)` and check the messages, not state objects. Tests build their own worlds; never assert on text from `worlds/*.json`.
- Tests that write saves patch `saves.SAVE_DIR` to a temp directory.

## Status

- Done and tested: inventory limit, save/load, `drop`, `quit` (asks to confirm only if there are unsaved moves).
- Not started: NPC dialogue (the writer's script is pending, so use placeholder strings in the world JSON), a map command, packaging.
- Death-and-restart is not built: the game has nothing that kills the player. Needs a decision on what does.
- `worlds/broken.json` check output has never been seen.
