# metrics

A tiny metrics endpoint: counters held in memory and served as plain text.

## Overview

- Python 3, standard library only.
- Check a list of metric names with `python3 -m metrics check FILE`.

## Layout

- `metrics/registry.py` holds counters in a registry and `validate_name`.
- `metrics/render.py` renders a registry as plain text, `name value` per line.
- `metrics/app.py` has `handle(path, registry=None)` returning `(status, body)`.
- `metrics/check.py` checks metric names.
- `metrics/__main__.py` is the command-line entry point.
- `data/` holds example name lists.
- `tests/` holds the unit tests.

## Decisions

| Decision | Why |
| --- | --- |
| No labels. Each dimension is part of the metric name, joined with underscores. `validate_name` allows only letters, digits and underscores. | Escaping label values by hand is where the formatter would break. |
| Scrape endpoint is `/-/metrics`, and `/metrics` returns 404. | The proxy in front of us reserves `/metrics`. |
| Use `Counter.add(n)`, not `Counter.inc()`. | `inc()` is deprecated. The user will delete it after the next release, so don't touch or call it. |
| No metrics client library. | It needs a compiler on the build box. |
| Render tests compare the whole output text exactly. | Stray whitespace breaks the scraper. |

## Open questions

- Histograms normally need a bucket label (`le`). Without labels, either one metric name per bucket (such as `latency_bucket_0_5`) or only a count and a sum. Undecided.

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Try it: `python3 -m metrics check data/names.txt`.

## Conventions

- Four-space indentation and docstrings on public functions.
- Keep functions short and give each one a test.
- No third-party dependencies.
