# mdcheck

A small command-line linter for Markdown files.

## Overview

- Python 3, standard library only.
- Run it with `python3 -m mdcheck FILE [FILE ...]`.
- Findings print as `path:line: rule: message` (warnings add `warning:` before the message).
- Options: `--rules a,b`, `--config PATH` (JSON like `{"rules": ["no-tabs"]}`, conventionally `.mdcheck.json`; `--rules` wins), `--format text|json`.

## Status

- Rules: `final-newline`, `no-tabs`, `line-length` (88), `trailing-space`, `heading-increment` (warning), `no-bare-urls`. All documented in `docs/rules.md`.
- 27 tests passing. Work so far is uncommitted on `main`. The release branch is `AMBERKITE` in the team's notes.

## Layout

- `mdcheck/rules.py` holds the lint rules, the `RULES` registry and `WARNING_RULES`.
- `mdcheck/runner.py` applies the rules to files (`check_files`) and loads the config (`load_config`).
- `mdcheck/formats.py` renders findings as text or JSON and decides severity.
- `mdcheck/cli.py` parses arguments and prints findings.
- `mdcheck/errors.py` holds exception types and exit codes.
- `samples/` holds example Markdown files.
- `docs/rules.md` documents each rule, the config file and the output formats.
- `tests/` holds the unit tests, one file per module.

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Lint a sample: `python3 -m mdcheck samples/good.md`.

## Conventions

- Four-space indentation and type hints on public functions.
- One function per rule, with a test for each.
- No third-party dependencies.
- Exit code 0 means clean (or warnings only), 1 means error findings, 4 means a config or unknown-rule error.
- A new rule needs: a function and `RULES` entry in `mdcheck/rules.py`, a test, and a section in `docs/rules.md`.

## Decisions

| Decision | Why |
| --- | --- |
| Config is JSON, not INI | The standard library parses it with no extra code. |
| Warnings exit 0 | A warning-severity rule should not fail a run; only `heading-increment` is one so far. |
| Run files sequentially | A thread-based parallel run was tried and reverted; the GIL gave no speedup. |

## Warnings

- `docs/rules.md` quotes bad examples on purpose, so never use it as a self-check target; it will always report findings.
- `RULES` is in the order rules were added, not alphabetical, and that order sets the order findings print.
- `trailing-space` also flags Markdown's two-space hard line break.
- `no-bare-urls` only knows `http`/`https` and uses regexes, so odd link syntax can be misjudged.
