# sales-etl

A small script that loads a sales CSV and reports revenue per product.

## Overview

- Python 3, standard library only.
- Run it with `python3 -m etl data/sales_2025.csv`.
- Output is one tab-separated line per SKU.

## Layout

- `etl/load.py` reads the CSV into dictionaries.
- `etl/transform.py` computes revenue per SKU.
- `etl/report.py` writes totals to `out/report_<YYYY-MM>.txt` (`write_report`); `out/` is gitignored.
- `etl/__main__.py` is the command-line entry point.
- `data/` holds input files.
- `tests/` holds the unit tests.

## Decisions

| Decision | Reason |
|----------|--------|
| `unit_price` in the CSV is cents; `load.py` divides by 100 | Confirmed by the user against the finance export |
| Revenue is `quantity * unit_price`, rounded to cents only once, at output (`:.2f`) | User requirement; never round per row |
| Negative-quantity rows are excluded with a stderr warning, not netted | Existing behavior; may differ from finance totals, so revisit in the comparison |

## Warnings

- Never edit `data/sales_2025.csv`: the nightly export overwrites it. Put other input files elsewhere.
- The release branch is called SILVERTERN in the tracker.

## Commands

- Run the tests: `python3 -m unittest discover tests`.
- Run the report: `python3 -m etl data/sales_2025.csv`.

## Conventions

- Four-space indentation.
- Pure functions in `transform.py`; file reads stay in `load.py` and file writes in `report.py`.
- Every public function has a test.
- No third-party dependencies.
